# 3. PROBLEM STATEMENT

==================================================

Organizations frequently struggle with fragmented workflows, repetitive coordination, disconnected information, delayed decisions, and manual task management across departments.

When a business issue occurs, employees often have to manually:

* Understand the issue
* Determine priority
* Break the issue into tasks
* Assign tasks to departments
* Communicate with different teams
* Track task progress
* Follow up on delays
* Escalate unresolved issues
* Prepare reports
* Decide what should happen next

This creates:

* Slow issue resolution
* Repetitive administrative work
* Poor coordination
* Missed deadlines
* Inconsistent decisions
* Lack of workflow visibility
* Increased employee workload

Traditional automation follows fixed rules.

Organizations need an intelligent system capable of understanding a problem, planning a multi-step workflow, delegating tasks, monitoring progress, detecting failures, and adapting its plan dynamically.

==================================================

# 5. MULTI-AGENT ARCHITECTURE

==================================================

Implement the following logical agents.

The agents may use the same Gemini API but MUST have separate responsibilities and prompts.

---

## ORCHESTRATOR AGENT

The central intelligence of the system.

Responsibilities:

* Receive workflow
* Understand objective
* Determine required agents
* Create execution plan
* Coordinate agents
* Monitor workflow state
* Detect failures
* Trigger replanning
* Decide whether human approval is needed
* Move workflow toward completion

The Orchestrator must maintain workflow state.

Possible states:

draft
analyzing
planning
ready
executing
monitoring
blocked
replanning
awaiting_approval
completed
failed

---

## ANALYSIS AGENT

Analyze the business problem.

Determine:

* Summary
* Category
* Priority
* Business impact
* Affected departments
* Recommended actions
* Missing information

Return structured JSON.

Example:

{
"summary": "Customer was charged but order was not created.",
"category": "Payment Issue",
"priority": "HIGH",
"impact": "MEDIUM",
"departments": ["Finance", "Support"],
"recommendedActions": [
"Verify payment",
"Check order creation",
"Prepare resolution"
]
}

---

## TASK PLANNING AGENT

Convert the analysis into actionable tasks.

Each task must contain:

* Title
* Description
* Priority
* Assigned Agent
* Dependencies
* Estimated duration
* Requires approval
* Status

Example:

{
"title": "Verify payment transaction",
"description": "Check whether the customer's payment was successfully processed.",
"priority": "HIGH",
"assignedAgent": "Finance Agent",
"dependencies": [],
"requiresApproval": false
}

---

## COORDINATION AGENT

Determine which agent or department should handle each task.

Possible agents:

* Finance Agent
* Technical Agent
* Support Agent
* Operations Agent
* Manager Agent

---

## EXECUTION AGENT

Execute permitted application-level actions.

Examples:

* Create task
* Update task
* Update workflow
* Generate report
* Generate response
* Create notification
* Prepare recommendation

For the hackathon, external real-world actions may be simulated.

---

## MONITORING AGENT

Monitor workflow progress.

Detect:

* Delayed tasks
* Failed tasks
* Blocked tasks
* Missing information
* Incomplete workflows

---

## REPLANNING AGENT

This is a critical feature.

When a task fails or becomes delayed:

1. Detect failure
2. Analyze reason
3. Determine alternative
4. Generate new plan
5. Reassign task
6. Escalate if necessary
7. Continue workflow

Example:

Finance Agent fails.

The system should produce:

"Finance Agent unavailable. Reassigning verification task to Backup Finance Agent and notifying Manager."

# 6. HUMAN-IN-THE-LOOP

==================================================

Not every action should be autonomous.

Low-risk actions may execute automatically.

High-impact actions require human approval.

Example:

AI recommendation:

"Approve customer refund of ₹4,500."

[ APPROVE ]

[ REJECT ]

When approved:

* Save approval
* Update database
* Continue workflow
* Add activity log

When rejected:

* Save rejection
* Ask AI for an alternative
* Update workflow
